# 確認用ツール

本体を作り込む前に、Zoom Meeting SDK が実際に何を渡してくるかを数字で確かめるための小さなツールです。
Zoom Meeting SDK はこのリポに含めていないので、ビルドには手元のSDKが必要です。

## 1. 受信の確認（backhaul_probe_receive）

会議に参加し、相手ごとの映像の大きさ・コマ数と、音声の形式を5秒ごとに記録します。
映像の表示や録画はしません。記録は画面と `backhaul-probe-receive.log` に出ます。

### ビルド

```
cmake -S . -B build -DBACKHAUL_ZOOM_SDK_DIR=<SDKを展開した場所>/x64
cmake --build build --config Release
```

できた `backhaul_probe_receive.exe` を、SDK の `x64/bin` フォルダーに置いて実行します。

### 実行

鍵類はコマンドに書かず、環境変数で渡します（履歴に残さないため）。

| 環境変数 | 内容 |
| --- | --- |
| `BACKHAUL_ZOOM_CLIENT_ID` | Zoomアプリの Client ID（必須） |
| `BACKHAUL_ZOOM_CLIENT_SECRET` | Zoomアプリの Client Secret（必須） |
| `BACKHAUL_ZOOM_PASSCODE` | 会議のパスコード（ある場合） |
| `BACKHAUL_ZOOM_ZAK` | ZAK（自分のアカウント以外の会議に入る場合） |

```
backhaul_probe_receive --meeting 12345678901 --name "会場PC" --resolution 1080 --seconds 120
```

- `--resolution` は 1080 / 720 / 360。頼んだ大きさと、実際に届いた大きさの両方を記録します。
- 参加しただけでは映像・音声は取れません。ホストがこの参加者を共同ホストにするか、録画の許可を出すと取り始めます。
- `--seconds` を省くと Ctrl+C を押すまで動きます。

### このツールで確かめること

- 1080p / 720p を頼んだとき、実際に届く大きさとコマ数（契約プランによる違い）
- 人数を増やしたときに大きさがどう変わるか
- 相手ごとの音声が 48kHz・モノラルで届くか
- 回線の状態の通知がどのくらいの細かさで来るか

## SDKのヘッダーから分かったこと（バージョン 7.2.5）

- 音声は 32kHz（既定）と 48kHz を選べる。
- 映像の色の規格は BT.601 / BT.709、それぞれ狭い範囲・広い範囲を選べる。
- 相手ごとの回線の状態を知らせる通知がある。
- 入り直しても変わらない参加者の番号を取る関数がある。
- `sdk.dll` は、読み込んだだけで初期化せずに終了すると異常終了する（実機で確認）。そのため必要になってから読み込む作りにしている。

実際の値がどうなるかは、会議につないで確かめるまで未確認です。
