# backhaul 入場券サーバーとライセンス — 設計書（承認待ち）

2026-11-28 作成。**まだ何も実装していない。** この設計と画面見本に OK が出てから作る。

## 1. 何を作るか

- PCごとに Zoom の鍵（Client ID / Secret）を入れる作業をなくす。代わりに **ライセンスキーを1回** 入れる。
- 「Zoomにサインイン」を1回しておくと、ほかのアカウントが開いた会議に入るための許可（ZAK）を、入るたびにアプリが自動で取る。
- 将来の販売を見すえ、ライセンスキーごとに「期限・使えるPCの台数・停止」を持たせる。

今回入れないもの：決済、購入ページ、キーの自動発行、管理画面（キーの発行は手元のコマンドで行う）。

置き場所：新しいリポは作らず、**backhaul リポの `server/` フォルダ** に置く（アプリと決まりごとを一緒に直せるため。鍵はコードに書かないので公開リポのままでよい）。

## 2. Zoom の決まり（公式情報で確認）

| 決まり | 出どころ |
|---|---|
| 入場券（JWT）は Client Secret で署名して作る。鍵を安全に置ける場所（サーバー側）で作ることが勧められている | https://developers.zoom.us/docs/meeting-sdk/auth/ |
| 入場券の期限は、作ってから最短30分、長くても48時間までが目安 | 同上 |
| 自分のアカウント以外の会議に入るには「Zoom の審査を通ったアプリ」＋「ZAK か OBF でユーザーを示すこと」の両方が要る | https://developers.zoom.us/docs/meeting-sdk/get-credentials/ |
| この決まりは 2026-03-02 から実際に効いている。入場券だけでは外の会議に入れない | https://developers.zoom.us/docs/meeting-sdk/obf-faq/ |
| ZAK は、サインイン（OAuth）でもらった券で `GET /v2/users/me/token?type=zak` を呼んで取る。通常2時間で切れる。使う直前に取るのがよい | https://developers.zoom.us/docs/meeting-sdk/auth/zak/ |
| サインインに要る権限は `user:read:token`（Zoom のブログの記載。アプリの設定画面で名前を最終確認する） | https://developers.zoom.us/blog/transition-to-obf-token-meetingsdk-apps/ |
| 審査は「一般公開」でなくてもよい（非掲載を選べる） | https://developers.zoom.us/changelog/platform/meeting-sdk-policy-announcement/ |

**大事な帰結**：お客さんが自社の Zoom で開いた会議に入れるのは、Zoom の審査が通ってから。それまでは「SEVENTHWELL のアカウントが開いた会議」でだけ動く。

## 3. 技術の選び方

### サーバー

| 候補 | 軽さ | 作りやすさ | 将来性 | AIでの書きやすさ | メモ |
|---|---|---|---|---|---|
| **Cloudflare Workers ＋ Hono（TypeScript）** | ◎ | ◎ | ◎ | ◎ | tower の共通の公開の仕組みにそのまま乗る。データは D1 |
| Vercel Functions | ○ | ○ | ○ | ◎ | 動くが、tower の仕組みの外になり、鍵の管理が二重になる |
| 自前のサーバー（VPS） | △ | △ | △ | ○ | 面倒を見る手間が大きい。止まると全現場が止まる |

**おすすめ：Cloudflare Workers ＋ Hono。** 既にある tower に乗り、止まりにくく、月額もほぼかからないため。

使うバージョン（npm の公式の登録情報で 2026-11-28 に確認した最新の安定バージョン）：

| 部品 | バージョン | 出どころ |
|---|---|---|
| Hono | 4.13.23 | https://www.npmjs.com/package/hono |
| Wrangler（公開の道具） | 4.169.0 | https://www.npmjs.com/package/wrangler |
| TypeScript | 7.0.2 | https://www.npmjs.com/package/typescript |
| Vitest（テスト） | 5.1.2 | https://www.npmjs.com/package/vitest |

### アプリ側の通信

| 候補 | 配布サイズ | 作りやすさ | テストのしやすさ | メモ |
|---|---|---|---|---|
| **Qt Network** | 小（DLL 1つ増える） | ◎ | ◎（Linux でも同じコードが動く） | 暗号は Windows 標準のものを使う |
| WinHTTP（Windows 標準） | なし | △ | △（Windows でしか動かない） | |
| libcurl | 中 | ○ | ○ | 部品が1つ増え、更新の面倒も増える |

**おすすめ：Qt Network。** 既に Qt を使っていて、Linux の自動テストでも同じコードを確かめられるため。

## 4. しくみ

```
アプリ（PC）                     入場券サーバー（Cloudflare）           Zoom
  │ ライセンスキー＋このPCの名前  │                                   │
  ├──────── 登録 ───────────────▶│ キーを確かめ、台数を数える          │
  │◀─────── このPC用の合言葉 ────┤                                   │
  │                              │                                   │
  ├──────── 入場券をください ───▶│ Zoomの鍵で署名（鍵はここだけ）      │
  │◀─────── 入場券（24時間） ────┤                                   │
  │                              │                                   │
  │ 「Zoomにサインイン」→ブラウザ ─────────────────────────────────▶│ サインイン・許可
  │                              │◀──────── 許可の合図 ───────────────┤
  │◀─────── サインインの券 ──────┤（サーバーは券を保存しない）         │
  │                              │                                   │
  ├──────── ZAKをください ──────▶├──────── ZAKを取る ───────────────▶│
  │◀─────── ZAK（その場かぎり）──┤◀──────────────────────────────────┤
  │
  └─ 入場券＋ZAK で会議に入る（ここは今までと同じ Zoom SDK）
```

### サーバーの窓口

| 窓口 | すること |
|---|---|
| `POST /v1/activate` | ライセンスキーとこのPCの番号・名前を受け取り、台数の枠に登録して「このPC用の合言葉」を返す |
| `POST /v1/deactivate` | このPCを枠から外す |
| `POST /v1/status` | 期限・台数・停止されていないかを返す |
| `POST /v1/sdk-token` | 入場券を返す（期限24時間） |
| `GET /v1/zoom/login` → `GET /v1/zoom/callback` | Zoom のサインイン画面へ送り、戻りを受ける |
| `POST /v1/zoom/collect` | サインインの結果（券）をアプリが1回だけ受け取る |
| `POST /v1/zoom/zak` | アプリが持つサインインの券から、ZAK を取って返す |
| `POST /admin/licences` ほか | キーの発行・一覧・停止（管理用の鍵が要る） |

### データ（D1）

| 表 | 中身 |
|---|---|
| licences | キーの指紋（元のキーは保存しない）、持ち主のメモ、台数、期限、停止の印 |
| devices | どのキーの何台目か、PCの名前、合言葉の指紋、最後に使った日時 |
| logins | サインイン中の一時的な受け渡し（10分で消える） |

Zoom のサインインの券は **サーバーに保存しない**。アプリが Windows の資格情報の保管場所に入れ、必要なときだけサーバーに渡して ZAK に替えてもらう。

### アプリ側

- `src/app/gate_client.{h,cpp}`：サーバーとやり取りする部分（テスト用の偽物に差し替えられる形）。
- `src/app/licence_controller.{h,cpp}`：ライセンスの状態、サインインの状態、画面への表示。
- `MeetingController`：会議に入るとき、①自分で入れた Zoom の鍵があればそれを使う ②なければサーバーから入場券をもらう。サインイン済みなら ZAK も一緒にもらう。
- ライセンスキー・このPC用の合言葉・サインインの券は、Windows の資格情報の保管場所に入れる。設定ファイルにもプロジェクトにも書かない。

## 5. 画面

「設定 → Zoom接続」の「Zoomアプリの鍵」と「ほかのアカウントの会議に入るとき」を、次の2つに置き換える（画面見本：`design/gate-zoom-set.png` 設定済み、`design/gate-zoom-empty.png` 未設定）。

**ライセンス**
- 未設定：ライセンスキーの欄と「確かめて保存」。
- 設定済み：「有効」、キーの末尾だけ、台数（例：PC 2 / 5台）、期限、このPCの名前。「入れ直す」「このPCを外す」。
- 「自分で作ったZoomアプリの鍵を使う」を押すと、今の Client ID / Secret の欄が開く（上級者向け。審査が通るまでの保険）。

**Zoomアカウント**
- 未設定：「Zoomにサインイン」。押すとブラウザが開き、許可するとアプリに戻る。
- 設定済み：名前とメール、「サインアウト」。
- 「サインインできないときは、許可コード（ZAK）を手で貼る」を押すと、今の欄が開く。

### 起こりうる状態と、出す文

| 状態 | 画面に出すこと |
|---|---|
| キーが違う | 「このライセンスキーは見つかりません」 |
| 台数がいっぱい | 「このキーは5台すべて使用中です。ほかのPCで『このPCを外す』を押すと空きます」（使用中のPCの名前を並べる） |
| 期限切れ・停止 | 「期限が切れています（2027-11-30まで）」／「このキーは止められています」 |
| サーバーに届かない | 「ライセンスのサーバーに届きません。ネットを確かめてください」。手元に期限内の入場券があれば、それで入れる |
| サインインが切れた | 「Zoomのサインインが切れました。もう一度サインインしてください」 |
| 審査前に外の会議へ入ろうとした | Zoom が返す理由をそのまま分かる言葉で出す |

## 6. 安全のための決まり

- Zoom の鍵は Cloudflare の「秘密の値」にだけ置く。コード・リポ・アプリには入れない。
- ライセンスキーは 100 ビット以上の乱数。サーバーには指紋（SHA-256）だけを保存する。
- このPCの番号は、インストールごとに作る乱数。部品の番号などPCを特定する情報は取らない。
- 入場券は 24 時間で切れる。停止したキーは、遅くとも 24 時間で使えなくなる。
- 総当たりを防ぐため、窓口ごとに回数の上限を付ける。
- 記録に残すのは「どのキーの何台目が、いつ入場券を取ったか」まで。会議IDや参加者の名前は送らない・残さない。

## 8. 進め方

1. **段階1（今回）**：サーバー、ライセンスキー、Zoom サインイン、画面の置き換え。SEVENTHWELL のアカウントの会議で動く。
2. **段階2**：Zoom の審査に出す。要るもの：独自ドメイン、プライバシーポリシー、利用規約、サポート窓口のページ、審査用のテスト手順。
3. **段階3**：決済とキーの自動発行。

## 9. 持ち主にお願いすること（段階1で、作ったあとに1回だけ）

- Zoom のアプリの設定画面で、サインインの戻り先の URL と権限 `user:read:token` を足す。
- Zoom の鍵を Cloudflare の「秘密の値」に入れる。

どちらも、その時に画面の直接 URL と押す場所を1つずつ書く。

## 10. まだ確かめられていないこと

- 権限の正式な名前（`user:read:token`）が、今のアプリの設定画面でその名前で出るか。
- 同じ Zoom アカウントで複数台が同時に会議へ入れるか（Zoom アカウント側の設定による）。役割ごとに何台も入るアプリなので、ここは実機で最初に確かめる。だめな場合は、2台目以降を「OBF（サインインした人の代理として入る）」に切り替える案がある。
- 審査にかかる日数と、映像・音声を取り出す機能に付く追加の条件。
- ASIO 入りを人に配るための Steinberg との契約（前からの宿題）。
